# v7 の変更点（ログインと記録の同期）

このフォルダ（app_v7）は、v6（app/）を変えずに複製して作った v7 です。

## 設定
`config.js` の `apiUrl` と `apiKey` を空のままにすると、v6 と同じく端末内だけで動きます（ログインなし）。
Supabase に反映したあと（`supabase/setup_guide.md`）、この2つを入れると、ログインが必須になります。
- `apiUrl`: `https://xxxx.supabase.co/functions/v1/api`
- `apiKey`: 公開用キー（`sb_publishable_...`）のみ。secret / service_role は入れない。

## 動き
- 生徒番号（6桁）と合言葉でログイン。成功するとトークンを端末に保存し、期限切れなら再ログイン。
- 学習記録は生徒ごとに端末内（`osaka-eng-v2_生徒番号`）へ保存し、解答・訳を見た文・利用履歴をサーバーへ送る。
  送れないとき（電波なし）は端末に貯めて、回線が戻ったとき・画面を閉じるとき・1分ごとに再送する。同じ記録を2回送っても二重にならない。
- 端末を変えてログインすると、端末内が空なら、サーバーの解答履歴から学習記録を復元する（演習の途中経過・精読の進み具合は端末内のみ）。
- v6 の記録が端末に残っていれば、ログイン後のホームに「取り込みますか」を表示。取り込み後も元データは消さない。
- ホーム最下部にログイン中の氏名・校舎、送信状況、ログアウトを表示。

## 変更したファイル
`app.js`（保存・送信・ログイン）、`sync.js`（新規。通信とID）、`config.js`（新規。設定）、`style.css`（末尾に追記）、`index.html`（スクリプトの読み込み）。

## 確認したこと
モックのサーバーで、ログイン失敗／成功、v6記録の取り込み、演習の解答の送信、練習の訳の記録、ログアウト後の再ログインと復元、期限切れトークン、通信なしの起動、設定なし（v6動作）を確認。実際のSupabaseとは未接続。

# 大阪府公立高校入試 英語 学習アプリ（試作）

## 開き方
このフォルダ（app）をまるごとパソコンやスマホに保存し、`index.html` をブラウザで開きます。
インターネット接続もサーバーもいりません。将来は、このフォルダをそのまま GitHub Pages に置けば公開できます。

## 中身
- `index.html` 画面の入口
- `style.css` 見た目
- `app.js` 動き（過去問演習、長文精読、文法、語彙、ランダム、学習記録）
- `data/data.js` 問題データ（自動生成。手で編集しない）

## データの作り直し
`dataset/tools/to_app.py` を実行すると、`dataset/json` と `dataset/enrich` から `data/data.js` を作ります。
Excel マスター（`dataset/tools/to_excel.py`）と同じ ID（例 2025-A-02-S07）を使っています。

    python3 dataset/tools/to_app.py app/data 2025-A [2025-B ...]

## 学習記録
ブラウザの localStorage（キー `osaka-eng-v1`）に保存します。別の端末やブラウザには引き継がれません。
「学習記録」画面から JSON で書き出せます。記録の項目：利用者ID（端末ごとの仮ID）、設問ID、解答、正誤、得点、
配点、解答時間、ヒント使用数、答えを見たか、再挑戦回数、日時、文法コード、問題形式。

## 採点のきまり
- 選択問題は自動採点。記述問題は公式解答・別解と一致すれば自動で正解、違えば自分で ○／△／× を付ける。
  条件英作文はいつも自己採点。
- ヒント1で8割、ヒント2で6割、答えを見ると0点（仕様書18章）。
- 得点は最初の解答で決まる。間違えたあとも「もう一度考える」で何度でも解き直せる（回数は記録される）。

## 過去問演習と過去問練習
試験ページの大問ごとに2つのボタンがあります。
- 過去問演習（`#/solve/大問ID`）：本番と同じ形。成績は学習記録に入る。
- 過去問練習（`#/practice/大問ID`）：本文の一文ごとに「訳」ボタンが付き、押すと和訳が出る（もう一度押すと閉じる）。「全部の訳を出す」で一括表示もできる。
  - 空所のある文は、その文に関わる設問に答える（または答えを見る）まで訳を出さない（和訳は答えを入れた文のため）。
  - 練習の成績は学習記録の集計・ランダムの「前回まちがえた」には入らない（記録に mode=practice を付けて区別。結果画面に「訳を見た文」の数を表示）。
  - 訳ボタンは本文のみ。設問の英文には付かない。

## マーキング
- すべて自動表示（自分で線を引く機能はない）。
- 主語（オレンジ枠）・動詞（ピンク枠）：節ごとに付く。精読・演習の本文、設問の英文に表示。「主語・動詞」ボタンで消せる。
- 解答の根拠（黄色）：演習では答えた（または答えを見た）設問の分だけ本文に出る。精読では「解答の根拠」ボタンで表示。
- 精読では「文法」の段階で、その文の文法すべてに下線が付く。下線の色は文法の種類（文の形・動詞の形・to/ing/分詞・関係代名詞/接続詞・その他の5色）。凡例と文法ボタンを英文の下に表示し、ボタン（または文法の欄）をタップするとその箇所だけが濃くなる。文法ページの例文にも下線。
- 主語・動詞と根拠のデータは dataset/markup/<試験ID>.json（作り方のルールは同じフォルダの README.md）。語の番号は app.js の WORD_RE で数える。

## 見た目
- デザインは「ノート」案（方眼の紙の背景、蛍光ペン風の見出し、付せん風の和訳）。明るい・暗いの両方あり、「配色」ボタンで切り替え。
- フォントは Google Fonts（Zen Kaku Gothic New・Lora）を読み込む。ネットにつながらないときは端末のフォントで表示される。
- 主語・動詞の枠と黄色の色はデザインと関係なく固定。

## 文法の呼び方
- 文型は「SVOC」などの記号を使わず、主語・動詞・目的語・補語で書く（文法名、解説、各文の「文構造」欄、設問の解説）。内部の文法コード（G-SVC など）は変えていない。
- 解説の中の文法用語（原形、過去分詞、先行詞、目的語、補語 など）は、最初の1回だけ点線になり、タップで意味が出る。一覧は「文法」画面の「文法用語の意味」（`#/terms`）。用語の定義は app.js の TERMS。

# スラッシュ分割（本文）

本文の英文に、意味のかたまりごとの区切り「 / 」を入れる表示です。例：My brother / has / a smartphone / in his bag.
- 全体の切り替え：画面上部の「/ スラッシュ」ボタン（主語・動詞の枠のボタンと同じ並び。設定は端末に記憶）。
- 一文ごとの切り替え：訳ボタンの隣の小さな「/」ボタン。全体の切り替えを押すと、一文ごとの設定はリセットされて全体に従います。
- 精読：文の下の「スラッシュ /」ボタン。授業の講師画面（class_teacher.html）：上のボタン「スラッシュ /：あり／なし」と、文ごとの「/」ボタン。
- 対象は本文の文だけ（設問の英文は対象外）。主語・動詞の枠、黄色、文法の下線、空所とは重なっても崩れません（空所に入る答えの中ほどには入りません）。
- データ：`data/data.js` の各文の `slash`（語番号の配列）。作り方・取り決めは `dataset/slash/README.md`。
- 変更したファイル：`app.js`、`reading.js`、`class_teacher.html`、`style.css`（末尾に追記）、`data/data.js`。授業の講師画面は `reading.js` の写しを使うため、app.js と reading.js は同時に直してください。

## 主語・動詞の枠の一文ごとの切り替え
- 訳・スラッシュのボタンの隣に「S/V」ボタン（精読は「主語・動詞の枠」ボタン）。全体のボタンを押すと一文ごとの設定は全体に揃います。
- 初期は全体「なし」。以前に「あり」で保存していた端末も、一度だけ「なし」に戻します（設定キー svReset）。授業の講師画面の設定キーは tc_sv2。
